# 全国空气质量数据监测与居民个人防护指南平台 - 实施计划

## 文档说明

本文档为 AI 开发者提供逐步实施说明，遵循以下原则：
- 每个步骤小而具体，可独立完成和验证
- 每个步骤包含测试验证方法
- 不包含代码，仅提供操作指示
- 优先使用成熟组件和库，避免重复造轮子
- 先后端开发完成后提供接口文档，再进行前端开发

---

## 第一阶段：后端基础设施搭建

### 1.1 项目初始化

#### 步骤 1.1.1：创建 Django 项目结构
**操作指示**：
1. 在项目根目录创建 `backend/` 文件夹
2. 使用 Django 命令创建项目 `air_quality_system`
3. 创建以下应用目录结构：
   - `apps/` - 业务应用目录
     - `accounts/` - 用户认证
     - `airquality/` - 空气质量数据
     - `rules/` - 防护规则管理
     - `articles/` - 文章资讯管理
     - `logs/` - 系统日志
   - `utils/` - 工具函数
   - `conf/` - 配置文件

**测试验证**：
- 运行 `python manage.py runserver` 确认项目可正常启动
- 访问 http://127.0.0.1:8000 看到 Django 欢迎页面

---

#### 步骤 1.1.2：配置 MySQL 数据库连接
**操作指示**：
1. 安装 `mysqlclient` 或 `PyMySQL` 驱动
2. 在 `settings.py` 中配置数据库连接：
   - 数据库名：`air_quality_db`
   - 字符集：`utf8mb4`
   - 时区：`Asia/Shanghai`
3. 创建本地 MySQL 数据库

**测试验证**：
- 运行 `python manage.py check` 无数据库连接错误
- 运行 `python manage.py migrate` 生成初始表

---

#### 步骤 1.1.3：安装和配置 DRF 扩展库
**操作指示**：
1. 安装以下第三方库：
   - `djangorestframework` - REST API 框架
   - `django-cors-headers` - 跨域支持
   - `django-filter` - 查询过滤
   - `drf-spectacular` - OpenAPI 自动文档
2. 在 `INSTALLED_APPS` 中注册以上应用
3. 配置 CORS 设置，允许前端开发服务器访问

**测试验证**：
- 访问 API 根路径看到 DRF 默认页面
- 浏览器控制台无 CORS 错误

### C. 技术选型说明

| 模块 | 技术选择 | 理由 |
|------|----------|------|
| 后端框架 | Django 5.2 + DRF | 成熟稳定，快速开发 |
| 数据库 | MySQL 8.0 | 关系型数据，广泛支持 |
| 前端框架 | Vue 3 | 现代化，生态完善 |
| UI 组件 | Element Plus | 组件丰富，中文友好 |
| 图表库 | ECharts | 功能强大，免费 |
| 样式框架 | Tailwind CSS | 快速开发，高度定制 |
| API 文档 | drf-spectacular | 自动生成，OpenAPI 标准 |

### D. 开发注意事项

1. **不要重复造轮子**：优先使用成熟的第三方库和组件
2. **前后端分离**：严格按照 API 接口文档开发，避免耦合
3. **数据验证**：前端验证提升体验，后端验证保证安全
4. **错误处理**：统一错误码和错误信息格式
5. **性能优化**：大数据量操作使用批量处理，添加必要索引
6. **安全性**：虽然密码明文存储，但仍需防止 SQL 注入和 XSS 攻击
7. **代码规范**：遵循 PEP 8（Python）和 ESLint（JavaScript）规范
8. **测试覆盖**：关键功能必须有测试用例

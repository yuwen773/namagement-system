# 天猫潮玩电商数据采集系统 - 产品需求文档 (PRD)

## 1. 文档概述
### 1.1 项目背景
随着潮玩（潮流玩具）市场的蓬勃发展，商品更新迭代迅速，价格与销量波动频繁。相关数据分散在天猫等电商平台的各个页面中，缺乏统一的整理与分析工具。本项目旨在构建一个基于 Python 的数据采集与可视化系统，帮助用户高效获取并分析潮玩商品数据。

### 1.2 产品目标
- **自动化采集**：解决人工收集效率低的问题，实现一键采集天猫潮玩商品数据。
- **集中化管理**：提供清洗后的高质量数据存储与管理功能。
- **可视化决策**：通过图表直观展示价格分布、销量排行等关键指标。

### 1.3 适用范围
本系统包含管理端与用户端，适用于需要监控潮玩市场数据的管理员及普通用户。

---

## 2. 用户角色与权限

| 角色 | 描述 | 核心权限 |
| :--- | :--- | :--- |
| **管理员** | 系统运维与数据管理者 | 数据采集控制、数据清洗管理、用户账号管理、查看所有数据图表。 |
| **普通用户** | 数据消费者 | 查看数据图表、查询商品详情、导出数据、管理个人信息。 |

---

## 3. 页面规划

本方案在保持系统简洁、低负担的前提下，通过合理拆分功能模块，满足管理端 5-6 个页面、用户端 4-5 个页面的结构要求。

### 3.1 公共页面
1.  **登录/注册页**
    *   **功能**：用户身份验证、新用户注册。
    *   **元素**：账号输入框、密码输入框、角色选择、登录/注册切换卡片。

### 3.2 管理端页面 (共 5 个核心页面)
1.  **系统仪表盘 (Dashboard)**
    *   **定位**：全局数据概览。
    *   **内容**：数据总量统计、价格区间分布图、品牌占比图、系统运行状态概览。
2.  **数据采集控制台 (Crawler Console)**
    *   **定位**：爬虫任务的触发与监控。
    *   **内容**：
        *   **核心操作**：“开始采集”按钮（支持演示模式）。
        *   **日志面板**：实时滚动显示采集日志（如“正在抓取第 1 页... 成功”）。
        *   **状态指示**：当前爬虫状态（空闲/运行中/完成）。
3.  **商品数据管理 (Data Manager)**
    *   **定位**：已入库数据的维护。
    *   **内容**：全量商品数据表格、搜索筛选栏、编辑/删除操作、批量导出。
4.  **用户权限管理 (User Admin)**
    *   **定位**：账号管理。
    *   **内容**：用户列表、冻结/解冻账号、重置密码、新增管理员。
5.  **个人中心 (Profile)**
    *   **定位**：管理员自身信息维护。
    *   **内容**：修改头像、修改密码、基本资料设置。

### 3.3 用户端页面 (共 4 个核心页面)
1.  **市场行情大屏 (Market Monitor)**
    *   **定位**：消费决策支持。
    *   **内容**：侧重于“值得买”的数据分析，如销量 Top10 榜单、近期降价商品推荐、热度趋势图。
2.  **商品资源库 (Product Library)**
    *   **定位**：数据的检索与浏览。
    *   **内容**：高级搜索（按价格、品牌）、商品卡片/列表展示、分页控件。
3.  **商品详情页 (Product Detail)**
    *   **定位**：单品深度分析。
    *   **内容**：商品大图、详细参数表格、该商品的历史价格走势（如有）、所属店铺信息、直达天猫链接。
4.  **个人中心 (Profile)**
    *   **定位**：同管理端个人中心，复用组件。

## 4. 功能需求详情

### 4.1 数据采集模块 (核心策略优化)
*   **输入**：预设的目标 URL（天猫潮玩相关类目）。
*   **处理策略 (稳健性设计)**：
    *   **预置数据 (交付标准)**：系统数据库需**预先导入不少于 10,000 条**真实有效的历史潮玩数据。这确保了无论爬虫是否实时运行，系统图表和列表都有丰富的数据展示，满足验收标准。
    *   **演示采集 (按钮功能)**：
        *   前端“开始采集”按钮默认触发**演示模式**。
        *   **行为**：实时抓取少量数据（如 1-2 页，约 20-40 条），并追加到数据库中。
        *   **目的**：快速演示“采集 -> 清洗 -> 入库 -> 刷新显示”的完整全链路，同时避免现场演示时因网络波动或反爬导致的长时间等待/失败。
*   **数据清洗**：自动去除重复项、处理缺失值、格式化价格（转为数字类型）与销量字段。
*   **输出**：结构化的商品数据存入 MySQL 数据库。

### 4.2 数据存储模块
*   **技术**：MySQL 数据库。
*   **表结构设计**：
    *   `users`：用户账号信息。
    *   `products`：商品核心数据（ID, 标题, 价格, 销量, 店铺, 图片, 采集批次/时间）。
    *   `crawl_logs`：采集日志记录。

### 4.3 数据可视化模块
*   **技术**：ECharts。
*   **图表要求**：
    *   **价格分布**：饼图或柱状图，展示如“0-50元”、“50-200元”、“200元+”的商品占比。
    *   **销量排行**：柱状图，展示销量最高的 Top 10 潮玩。
    *   **店铺/品牌分析**：展示哪些店铺/品牌的商品数量最多。

### 4.4 用户管理模块
*   **鉴权**：登录状态拦截，区分管理员与普通用户权限。
*   **管理**：管理员可对违规用户进行封号处理。

---

## 5. 非功能需求
1.  **性能要求**：
    *   **海量数据响应**：在 10,000+ 条数据量级下，数据列表页需采用**后端分页**，保证首屏加载时间 < 1秒。
    *   **采集稳定性**：爬虫需设置合理的超时时间，防止进程僵死。
2.  **易用性**：
    *   采集过程需有明确的 UI 反馈（如 loading 动画或日志滚动），不能让用户感觉系统卡死。
3.  **兼容性**：
    *   前端页面适配主流浏览器（Chrome, Edge）。

# 非物质文化遗产数据可视化系统（管理员/用户双角色）实施方案

## 1) 目标与范围（Summary）
- 构建一个前后端可运行的系统（不含部署与高可用建设），支持管理员与普通用户两类角色。
- 技术栈固定为：
  - 前端：Vue 3 + TypeScript + Element Plus + ECharts + Tailwind CSS
  - 后端：Django 5.2 + Django REST Framework + MySQL
- 核心业务目标：驾驶舱总览 + 世界地图分布，并包含基础数据管理闭环。
- 数据由你后续提供在项目 `dataSouce` 目录，系统需完成：清洗、增强、导入。

## 2) 功能边界（In/Out of Scope）
- In Scope（首版必须）：
  - 登录鉴权（账号密码 + JWT）
  - 角色权限（管理员全管理、用户只读）
  - 驾驶舱总览（统计卡片、趋势、分类占比、地域分布）
  - 地图可视化（世界国家级）
  - 项目库管理、传承人库管理、分类统计
  - Excel/CSV 导入 + 数据校验 + 增强 + 入库
- Out of Scope（首版不做）：
  - 生产部署编排、容灾高可用
  - SSO、复杂工作流审批
  - NLP 智能推荐类能力

## 3) 系统架构与模块拆分
- 后端模块：
  - `auth`：用户登录、JWT 签发与刷新、角色鉴权
  - `heritage`：非遗项目 CRUD、查询、筛选、统计
  - `inheritor`：传承人 CRUD、关联项目、统计
  - `taxonomy`：类别与级别字典管理
  - `geo`：国家标准化、国家编码映射、坐标补全服务
  - `importer`：Excel/CSV 上传、解析、校验、清洗、增强、入库、导入日志
  - `dashboard`：聚合统计 API（地图、趋势、占比、排行）
- 前端模块：
  - 公共：登录页、路由守卫、权限指令、统一请求层
  - 用户端（只读）：驾驶舱、项目查询、传承人查询、详情页
  - 管理端：项目管理、传承人管理、分类字典、数据导入、导入记录与错误下载

## 4) 数据模型与关键接口（Public APIs / Interfaces / Types）
- 关键数据表（新增）：
  - `users`（含 role：`admin`/`user`）
  - `heritage_items`
  - `inheritors`
  - `categories`
  - `regions`（国家代码、国家名称、中心点经纬度、所属洲）
  - `import_jobs`
  - `import_errors`
- 关键字段约束（默认）：
  - 非遗项目：名称、类别、级别、国家、地区（可空）、保护单位（可空）、简介（可空）
  - 传承人：姓名、性别（可空）、所属项目、级别（可空）、国家、地区（可空）
- API（新增）：
  - `POST /api/v1/auth/login`
  - `POST /api/v1/auth/refresh`
  - `GET /api/v1/dashboard/overview`
  - `GET /api/v1/dashboard/map-distribution`
  - `GET /api/v1/dashboard/trends`
  - `GET /api/v1/heritage-items` / `POST` / `PUT` / `DELETE`
  - `GET /api/v1/inheritors` / `POST` / `PUT` / `DELETE`
  - `POST /api/v1/import/upload`
  - `GET /api/v1/import/jobs`
  - `GET /api/v1/import/jobs/{id}/errors`
- 前端类型（新增）：
  - `UserRole`, `HeritageItemDTO`, `InheritorDTO`, `DashboardOverviewDTO`, `MapPointDTO`, `ImportJobDTO`, `ImportErrorDTO`

## 5) 数据清洗/增强/导入流程（Decision Complete）
- 输入：`dataSouce` 目录下 Excel/CSV 文件（管理员在后台触发导入）。
- 流程：
  1. 文件解析（编码/表头/空值基础检查）
  2. 字段标准化（去空格、全半角、同义词归并）
  3. 地理信息标准化（国家名称映射到 ISO-3166 代码）
  4. 经纬度补全（按国家中心点回填，缺失则标记错误）
  5. 分类标签增强（按类别字典规则映射）
  6. 唯一性与关联校验（重复项目、传承人关联合法性）
  7. 入库（事务批处理）+ 导入报告生成
- 错误处理：
  - 失败行不入库；成功行入库
  - 输出错误明细（行号、字段、原因、建议修正）

## 6) 页面与可视化设计清单
- 驾驶舱：
  - 总量卡片（项目数、传承人数、类别数、国家覆盖数）
  - 世界地图（国家级热力/散点，可联动国家统计列表）
  - 类别占比（饼图）
  - 年度趋势（折线/柱状）
  - 国家排行（条形图）
- 列表页：
  - 项目库：关键词、类别、级别、国家筛选 + 分页
  - 传承人库：姓名、级别、所属项目、国家筛选 + 分页
- 管理页：
  - 字典管理（类别、级别）
  - 数据导入（上传、预览、执行、查看日志）

## 7) 权限与安全
- JWT 鉴权，前端请求头携带 `Authorization: Bearer <token>`
- 路由级与接口级双重权限校验
- 管理接口仅 `admin` 可访问；`user` 仅可读接口
- 登录失败次数与基础限流（应用层）

## 8) 测试与验收（Test Cases & Scenarios）
- 单元测试：
  - 国家映射、标签增强、去重规则、权限判断
- 接口测试：
  - 登录/刷新 token
  - 管理员 CRUD 全流程
  - 用户只读访问与越权拦截
  - 导入成功/部分失败/全失败三类场景
- 前端测试（至少关键流程）：
  - 登录与权限路由
  - 驾驶舱图表渲染与筛选联动
  - 导入页面状态流转
- 验收标准：
  - 1.1 万条以内数据可稳定导入
  - 地图、趋势、占比、排行在 3 秒内完成首屏渲染（本地开发环境基准）
  - 用户无法访问管理功能；管理员可完成全管理闭环

## 9) 实施阶段（建议顺序）
1. 项目脚手架与基础设施（前后端初始化、JWT、数据库连接、基础路由）
2. 核心数据模型与 CRUD（项目/传承人/分类/地区）
3. 导入管道（上传→清洗→增强→入库→日志）
4. 驾驶舱聚合接口与前端图表落地
5. 权限加固、联调、测试与验收

## 10) 明确假设与默认值（Assumptions）
- `dataSouce` 将在实现阶段提供，且主要为 Excel/CSV。
- 数据规模约 1 万，最大不超过 1.1 万。
- 地图范围为世界国家级，不做区县级深钻。
- 首版以 PC 优先并提供基础移动适配。
- 首版不包含部署、高可用、SSO 与智能推荐能力。

# 旅游景点推荐系统产品需求文档 (PRD)

## 1. 文档概述

### 1.1 项目背景
随着旅游业的发展，用户对于获取个性化、高质量的旅游景点信息需求日益增长。本项目旨在构建一个基于 Django 的旅游景点推荐系统，通过整合景点信息、用户评价及行为数据，为用户提供智能化的景点推荐服务，同时为管理员提供高效的信息管理和数据统计工具。

### 1.2 文档目的
本文档旨在明确“旅游景点推荐系统”的功能需求、页面结构及业务逻辑，为开发团队、测试团队提供详细的执行依据，确保项目按质按量交付。

### 1.3 适用范围
本系统包含 Web 端管理后台（供管理员使用）和 Web 端前台（供普通用户使用）。

---

## 2. 角色定义

| 角色 | 描述 | 核心权限 |
| :--- | :--- | :--- |
| **管理员 (Admin)** | 系统的运营维护人员 | 用户管理、景点信息管理、评论审核、公告发布、数据统计查看 |
| **普通用户 (User)** | 系统的终端使用者 | 浏览景点、搜索、收藏、评论评分、消息通知查看、个人中心管理 |

## 3. 页面结构 (Sitemap)

根据需求控制页面数量，登录/注册页不计入统计。

### 3.1 管理端 (Admin) - 约 7 个核心页面
1.  **数据看板 (Dashboard)**
    *   展示月度数据报告（新增用户、浏览量等）。
    *   展示景点热度排行 TOP 列表。
2.  **用户管理页**
    *   用户列表展示。
    *   用户权限控制（启用/禁用）。
    *   用户基本信息查看。
3.  **景点列表管理页**
    *   景点信息的分页列表展示。
    *   提供搜索/筛选功能。
    *   操作入口：编辑、删除、新增。
4.  **景点编辑/新增页**
    *   景点详细信息的录入表单（名称、图片、简介、地址、开放时间等）。
5.  **评论审核管理页**
    *   全站评论列表。
    *   违规评论驳回/删除操作。
6.  **公告/通知管理页**
    *   发布系统公告。
    *   历史公告列表管理。
7.  **个人设置页**
    *   管理员自身信息修改。
    *   修改密码。

### 3.2 用户端 (User) - 约 7 个核心页面
1.  **首页 (Home)**
    *   个性化推荐模块（基于用户偏好）。
    *   热门景点展示。
    *   全局搜索入口。
2.  **景点列表/搜索结果页**
    *   按类别、地区筛选景点。
    *   展示搜索结果列表。
3.  **景点详情页 (Detail)**
    *   景点基本信息（图文、参数）。
    *   评论与评分展示区。
    *   发表评论/评分交互区。
    *   收藏/取消收藏按钮。
4.  **个人中心 (User Center)**
    *   个人资料查看与编辑。
    *   修改密码。
    *   账号注销入口。
5.  **我的收藏页**
    *   展示用户收藏的景点列表。
    *   移除收藏操作。
6.  **我的评论页**
    *   展示用户历史发表的评论。
    *   删除评论操作。
7.  **消息中心页**
    *   展示系统公告。
    *   展示系统相关通知（如系统更新）。

## 4. 功能详情

### 4.1 账号与权限模块 (公共)

#### 4.1.1 注册与登录
*   **功能描述**：提供账号注册和登录功能。
*   **逻辑**：
    *   注册：校验用户名唯一性、密码强度。
    *   登录：区分管理员与普通用户，鉴权后跳转至对应首页。

#### 4.1.2 个人信息管理
*   **功能描述**：用户/管理员修改自身基础信息（姓名、联系方式等）及密码。
*   **逻辑**：修改密码需验证旧密码；修改敏感信息需二次确认。

#### 4.1.3 账号注销 (仅用户)
*   **功能描述**：用户可申请注销账号。
*   **逻辑**：用户提交申请 -> 管理员后台审核（或逻辑删除）-> 数据保留但账号不可用或彻底清除（视合规要求定，建议逻辑删除）。

---

### 4.2 管理端功能

#### 4.2.1 数据统计 (Dashboard)
*   **景点热度统计**：基于浏览量、评论量、评分加权计算热度值，展示 Top N 景点。
*   **月度数据报告**：图表展示每月新增用户数、景点浏览总量、新增评论数。

#### 4.2.2 用户管理
*   **列表展示**：显示所有注册用户。
*   **权限控制**：管理员可“禁用”违规用户账号，禁用后该用户无法登录；也可“开启”恢复。

#### 4.2.3 景点管理
*   **信息维护**：
    *   新增/编辑：录入名称、地址、类别、开放时间、简介、封面图、轮播图等。
    *   删除：软删除或硬删除景点数据。
*   **列表查询**：支持按名称、类别检索。

#### 4.2.4 评论审核
*   **内容监管**：管理员查看用户提交的评论。
*   **处理**：对涉及违规、敏感词的评论进行删除或驳回，系统自动发送通知给相关用户。

#### 4.2.5 通知管理
*   **系统公告**：管理员可发布全站公告（如系统维护、活动通知），所有用户可见。
*   **公告维护**：支持对已发布的公告进行删除或编辑。

---

### 4.3 用户端功能

#### 4.3.1 景点浏览与搜索
*   **推荐展示**：
    *   首页展示“猜你喜欢”，基于协同过滤或内容推荐算法（利用用户的历史浏览、收藏、评分数据）。
*   **列表筛选**：支持按地区、类别（如自然风光、人文古迹）筛选。
*   **搜索**：支持关键词模糊搜索景点名称。

#### 4.3.2 景点详情交互
*   **信息展示**：清晰展示景点属性及介绍。
*   **收藏功能**：点击收藏按钮，将景点加入“我的收藏”；再次点击取消。
*   **统计展示**：显示该景点的平均评分及评论总数。

#### 4.3.3 评论与评分
*   **发表评价**：
    *   用户需登录后方可操作。
    *   评分：1-5 分（或 1-10 分）。
    *   文本评论：输入具体评价内容。
*   **评论管理**：用户在“我的评论”页可删除自己发布的评论。

#### 4.3.4 消息通知
*   **系统通知**：接收并查看管理员发布的系统公告。
*   **交互通知**：接收评论审核结果（如评论被驳回）或其他互动消息。
*   **消息状态**：支持将消息标记为已读或删除。

## 5. 非功能需求

### 5.1 性能要求
*   页面加载时间：普通页面 < 2秒，复杂列表页 < 3秒。
*   并发支持：支持一定量的并发访问，保证推荐算法计算不阻塞主流程。

### 5.2 开发测试便捷性
*   密码存储：采用明文存储，无需加密校验

### 5.3 易用性
*   界面简洁美观，符合主流 OTA (Online Travel Agency) 平台操作习惯。
*   响应式设计，适配不同尺寸的 PC 浏览器。

### 5.4 界面美观性
*   使用 `frontend-design` skill 来设计**所有的**前端页面

## 6. 数据逻辑说明

### 6.1 推荐算法逻辑 (简述)
*   **输入数据**：用户画像、用户历史行为（浏览、收藏、评分）、景点属性。
*   **策略**：
    *   **冷启动**：对于新用户，推荐热度最高的景点。
    *   **个性化**：基于 Item-based CF (基于物品的协同过滤) 或 User-based CF，推荐相似用户喜欢的景点或与用户历史喜欢相似的景点。

### 6.2 热度计算公式 (示例)
`热度值 = (浏览量 * 0.2) + (评论数 * 0.3) + (平均评分 * 浏览量 * 0.5)`
*(具体权重可根据运营情况调整)*

## 二、数据清理方案

### 2.1 需要删除的数据

```sql
-- 1. 删除测试用户账号
DELETE FROM users WHERE username IN ('test_user1', 'test_user2');

-- 2. 删除旧的排班计划（2026-01-27 ~ 2026-01-31）
DELETE FROM schedules WHERE work_date BETWEEN '2026-01-27' AND '2026-01-31';

-- 3. 删除旧的考勤记录（2026-01-27 ~ 2026-01-31）
DELETE FROM attendance_records WHERE DATE(clock_in_time) BETWEEN '2026-01-27' AND '2026-01-31';

-- 4. 删除无意义的调班申请
DELETE FROM shift_swap_requests WHERE reason LIKE '调班测试%';

-- 5. 删除无意义的请假申请
DELETE FROM leave_requests WHERE reason LIKE '请假测试%';

-- 6. 删除无意义的异常申诉
DELETE FROM appeals WHERE reason LIKE '申诉测试%';
```

- 8条有效用户账号

## 四、业务流程覆盖

### 4.1 完整业务场景

✅ **考勤管理**
- 正常签到签退
- 迟到/早退/缺卡异常
- 加班记录与计算
- 异常申诉与修正

✅ **调班管理**
- 员工发起调班申请
- 管理员审批（通过/驳回）
- 调班后排班更新

✅ **请假管理**
- 病假/事假/调休申请
- 管理员审批流程
- 请假与考勤联动

✅ **薪资管理**
- 薪资生成（草稿）
- 薪资发布
- 员工申诉
- 管理员调整
- 薪资重新发布

### 4.2 完整申诉流程示例

```
1. 员工发现加班费计算错误
   ↓
2. 提交薪资申诉（SALARY, PENDING）
   ↓
3. 管理员审核并批准
   ↓
4. 薪资记录状态变为 APPEALED → ADJUSTED
   ↓
5. 调整加班费并重新发布
```
